# Connector Readiness Registry

Этот реестр — источник правды по фактической готовности каналов поставщика из ТЗ v3. Он запрещает смешивать готовность внутреннего кода с подтверждённой работой во внешнем контуре.

## Правила статусов

- `READY / PARTIAL / BLOCKED` — полнота внутренней бизнес-цепочки.
- `INTERNAL_READY` — код и локальный сценарий существуют, но production readiness не заявляется.
- `CONNECTOR_NEEDED` — необходимы внешние credentials, агент, tenant, mapping или реальная база.
- `PILOT` — выполняется ограниченный реальный пилот.
- `LIVE_VERIFIED` — реальный end-to-end сценарий пройден, evidence и `lastVerifiedAt` сохранены.

Реестр доступен оператору через `GET /api/integrations/readiness`; изменение — через `PATCH /api/integrations/readiness/:providerCode` с permission `integration.manage`. Каждое изменение аудируется.

## Минимальное evidence для LIVE_VERIFIED

| Канал | Обязательное подтверждение |
|---|---|
| Manual | 20 товаров, массовое изменение цены/остатка/статуса, подтверждение заказа |
| Excel/CSV | 1000+ строк, preview, выбранный режим импорта, повторный импорт без потерь, заказ |
| МойСклад | реальный tenant: товары/модификации/цены/склад/резерв/заказ/отмена/release, webhook retry и reconcile |
| 1С | installer и подписанный binary, ограниченный пользователь, реальная база, offline/retry/restore, заказ/резерв/отмена |
| Custom API | tenant-specific mapping, HMAC/auth, smoke и полный order/reservation cycle |

## Целевое время первого запуска

- Manual: тестовый offer 15–20 минут, тестовый заказ до 30 минут.
- Excel/CSV: 30–60 минут, тестовый заказ до 2 часов.
- МойСклад: credentials до 30 минут, тестовый заказ до 1 часа.
- Типовая 1С: 1–3 часа, запуск в тот же день.
- Нетиповая 1С/API: после mapping и smoke, до одного рабочего дня.

Непройденный внешний тест остаётся явным blocker в реестре; его нельзя закрыть демонстрационными данными.
