# ТЗ v4 — статус реализации

## Реализовано

- Платформенная оферта фиксируется при регистрации: версия, время, IP, user-agent, способ акцепта, хэш текста оферты и evidence snapshot.
- Создана отдельная сущность `PlatformOfferAcceptance`, связанная с организацией, пользователем и регистрационной заявкой.
- Публикация оффера больше не требует отдельного договора поставщик ↔ платформа и двух подписей оператора.
- Точная строка импорта автоматически получает подтверждённый match и DRAFT SupplierOffer.
- При наличии валидных цены, валюты и остатка автоматически создаются цена и остаток по первому активному складу поставщика.
- Повторная загрузка сохраняет подтверждённую связь по тому же external item и не требует повторного ручного matching.
- Для строки импорта сохраняется построчный complianceStatus: `READY`, `REVIEW_REQUIRED`, `DOCUMENT_REQUIRED`, `BLOCKED`, `EXPIRED`.
- Кабинет поставщика больше не показывает «Договор с платформой» как обязательный шаг onboarding.
- Добавлен опциональный рамочный договор `BuyerSupplierAgreement` между поставщиком и клиникой: две подписи ЭЦП, статусы ожидания/активации/непродления/истечения, ежегодная автопролонгация.
- Для уже активного договора повторное окно подписи недоступно; при отсутствии договора checkout не блокируется и заказ получает режим `ONE_TIME`.
- При наличии действующего рамочного договора заказ получает режим `FRAMEWORK_AGREEMENT` и ссылку на договор.
- Добавлена версионируемая `SupplierMappingMemory`: повторный импорт использует сохранённое сопоставление, а ручной override создаёт новую версию и помечает прежнюю как `REVOKED`.

## Проверено

- Новый v4 onboarding: регистрация и акцепт оферты — HTTP 201; запись акцепта создана в базе.
- Смешанная строка импорта: 1/1 обработана, exact match подтверждён, DRAFT-оффер создан автоматически с ценой и остатком.
- Публикация оффера без активного platform agreement теперь должна отклоняться договорным gate; после активации договора публикация проходит только при ACTIVE-карточке, цене, свежем остатке и compliance.
- API typecheck, build и supplier-web typecheck прошли.
- API поднял новые маршруты `/api/buyer-supplier-agreements/*`; Prisma schema, API build/typecheck и supplier-web typecheck проходят.
- EDS callback теперь reconciles и рамочный договор клиника–поставщик, а не только legacy-договор платформы; проверяются HMAC, replay, checksum документа, BIN и срок действия сертификата.
- `MarketplaceAgreementsService.assertActive()` подключён к публикации, marketplace visibility, supplier confirmation, checkout offer resolution, payment capture и внешнему order export; expired/non-signed agreements fail closed.
- 10 363 production canonical-карточки проверены: 0 без `ProductVariant`, 0 без `ProductCategory`, 0 без `ProductIndustry`; 10 363 поисковых документа заполнены. Mapping review для публичных источников сформирован в `data/supplier-mapping-review.csv` (10 168 строк); все импортированные карточки остаются DRAFT до supplier confirmation.
- Межкабинетный переход переведён на одноразовый handoff-код: access token не передаётся в URL, код живёт 120 секунд, хранится только hash и после обмена помечается использованным.
- Главный поиск магазина понимает стоматологический сленг и раскладку: словарь расширен более чем 100 профессиональными alias-группами, добавлены исправления типовых опечаток, фильтры фасовки/единицы/доставки и усиление точных совпадений.
- Добавлена `SearchQueryEvent`-аналитика и операторский endpoint `/api/marketplace/search/analytics`; в админ-контуре появился блок качества каталога, индекса и запросов без результата.
- Для поставщика добавлен `/api/suppliers/:supplierOrganizationId/onboarding-readiness`: организация, credentials, склад, источник, импорт, matching memory, договор ЭЦП, offer, цена и свежий остаток проверяются одной readiness-цепочкой.
- Production-каталог переквалифицирован без технической категории `imported-catalog`: карточки получили широкие отраслевые категории (терапия, эндодонтия, хирургия, ортодонтия, имплантология, инструменты, оборудование и др.) с сохранением поисковых categoryIds.

## Ещё не закрыто v4

- Целевой canonical-каталог 5 000–10 000 вариантов выполнен с запасом: в production сохранено 10 363 canonical DRAFT-карточки, включая 5 398 из Denti.kz, 1 376 из публичного AMDgroup sitemap-прохода и партии Dentalmarket/DM Market/DDD, Mediclus, NORD STOM, СТОМир и Profident-S. Публичные цены и остатки не превращаются в оферты автоматически.
- Боевой gateway ЭЦП и PSP sandbox подключаются через внешние credentials; текущий EDS/payment adapter fail-closed без gateway, а внутреннее тестирование использует mock-провайдер.
- Миграции договора и Mapping Memory применены на целевой production Supabase; контрольная проверка таблиц, индексов, шаблона договора и `_prisma_migrations` пройдена.
- Коннекторы 1С, МойСклад, OCR и внешняя проверка реестров остаются следующей очередью.
