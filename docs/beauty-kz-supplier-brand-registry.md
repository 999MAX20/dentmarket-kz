# Beauty KZ: реестр поставщиков и брендов

Этот реестр — подготовительный слой для запуска вертикали `beauty-kz`. Он не создаёт организации, не публикует товары и не подтверждает право поставщика продавать бренд. До коммерческого onboarding нужны BIN, юридические документы, договор, источник прайса и подтверждение полномочий на конкретный бренд.

Источник данных: публичные страницы поставщиков, зафиксированные в `data/verticals/beauty-kz/supplier-brand-registry.json`. Статус `SELF_CLAIMED` означает только публичное заявление поставщика или наличие брендовой страницы; это не заменяет проверку документов.

## Текущий срез

- 12 кандидатов-поставщиков для первичного outreach.
- 44 уникальные брендовые позиции с привязкой к источнику.
- 12 категорий Beauty уже заведены в taxonomy, но остаются `INACTIVE` до сертификации.
- Все бренды пока находятся в `SELF_CLAIMED`; `APPROVED` появится только после документальной проверки.

## Правильный порядок работ

1. Зафиксировать бренд в реестре и убрать дубли по canonical key.
2. Отправить поставщику onboarding-запрос: BIN, организация, контакт, склад, договор ЭЦП и источник каталога.
3. Получить XLSX/CSV/PDF или API и сохранить источник с tenant-specific mapping.
4. Сопоставить SKU, бренд, категорию и вариант с canonical product; не создавать дубль карточки.
5. Провести compliance для профессиональных и ограниченных товаров.
6. Создать offer поставщика с ценой, остатком и сроком поставки.
7. Опубликовать только после активного договора и подтверждения карточки.

Проверка файла запускается командой:

```bash
node scripts/validate-beauty-supplier-brand-registry.mjs
```
